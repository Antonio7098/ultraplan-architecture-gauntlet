### Architecture assessment

The module-driven structure is sound and repeatedly proven: surfaces compose through injected runners; `web -> app` and runcontrol-leaf boundaries are machine-enforced; the change-06 probe ("add review/smoke strategy") found the edit surface matches expectations in all five scenarios; `platform/runtime` is earned boundary translation; `internal/app` performs real projection/fingerprint/classification work, not forwarding. Roadmap fences themselves are unusually precise (Sprint 35 may pick operational storage; product-artifact persistence is Gate D).

The stress is concentrated where policy was copied instead of owned: (1) failure-persistence decisions live per hand-copied branch in seven flow functions and have already diverged (F01); (2) ordered stage vocabulary is re-enumerated by hand in ~12 lists outside `sprint.PlanningStages()` with no parity test, and the newest stage escaped four of them (F05, F08); (3) the observability payload vocabulary has three producer-side promotion layers but a frozen storage allowlist that deletes exactly what the newest commits promote (F02); (4) implementation moved product state into SQLite ahead of the recorded authority decision, silently co-tenanting the operational database (F03, F04); (5) doc contracts pinned by tests describe an older vocabulary than the code emits (F07).

### Defended architecture / rejected hypotheses

1. **"`internal/app` is a pass-through layer over product services"** — Rejected. Verified `PrepareOperation` builds confirmations with distinct per-kind warnings ("runtime-free; no runtime-backed writes" vs "MAY REFRESH FLOW-STATE.JSON"), issues fingerprints over governed inputs, and classifies typed operation errors (`app/operations.go:160-200`, `ErrStaleOperation` at `:166`); none exists in product packages.
2. **"Consolidate sprint/study twins (locks, cleanup_uncertain, atomic writes today)"** — Rejected for locks/state: implementations materially differ (central two-attempt retry vs per-study force-unlock/fsync/command sanitization); consolidation would couple deliberately independent product modules against the ownership doctrine. Only the mechanical file primitive crosses the threshold (F10), which the contract itself sanctions.
3. **"Roadmap forbids SQLite"** — Rejected as stated: the Sprint 35 fence explicitly permits operational-record persistence ("may persist operational run records using the smallest mechanism proven by reasoning"); the violation is scoped to *product* artifacts and timing (F03). Precision matters here or the arbiter will over-reach.
4. **"Unify the two supervision engines wholesale"** — Partially rejected. They translate different event vocabularies (`runtime.Event` vs `OperationEvent`); full merge adds indirection. The genuine duplication is the coalescing/omission bookkeeping skeleton and the terminal-proposal epilogue — a narrow helper suffices (specialist-24a-F03's remedy stands).
